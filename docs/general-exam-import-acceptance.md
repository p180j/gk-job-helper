# 通用招考数据导入与资格条件解析升级验收报告

生成日期：2026-10-27  
解析版本：`GENERAL_EXAM_V2`

> 本报告中的“完整/部分/无法解析”是基于规则状态的保守覆盖统计，不是人工标注准确率，也不是关键词命中率。未对生产 MySQL 执行迁移、导入、重建或恢复操作；真实文件回归均在测试配置的隔离 H2 数据库中完成。

## 1. 原有系统根因分析

1. Excel 预览和读取链路对默认 Sheet、固定表头位置及单一表头结构依赖较强，多 Sheet、说明 Sheet、父子表头和表头错位容易被静默遗漏。
2. 表头语义混用：“其他条件”容易并入备注，“工作地点”容易由地区或落户地点代替，导致资格条件丢失或地点含义错误。
3. 导入身份缺少文件校验值、解析版本和逐 Sheet/逐行溯源约束；职位代码在不同机关间可能重复，不能作为全局唯一键。
4. 备注匹配以整段结果为主，已识别的性别、年限等片段可能掩盖同段中未识别的硬性限制；条件来源、缺失档案和人工核验原因不够细。
5. 工作经历主要依赖汇总年限，不能可靠处理多段经历的时间并集、单位性质、行业、地区、单位层级、在职状态及材料状态组合。
6. 工作地点缺少明确地点、机关推断、多地点和未知之间的统一状态；落户地点存在被误当作工作地点的风险。
7. 派生字段重建缺少重建前快照和按批次恢复能力，解析器升级后的变更难以安全审阅和回退。

## 2. 完整模块修改说明

- Excel：统一 `ExcelRowReader` 供预览与正式导入复用，支持 `.xls/.xlsx`、多 Sheet、说明/空 Sheet、前 30 行表头探测、父子表头、列重排、别名、未知列、公式格式化和文本前导零。
- 映射：为每个 Sheet 独立保存映射；关键字段无法可靠映射时阻止导入并显示错误；未知/重复表头要求人工确认。
- 导入：新增 SHA-256、解析版本、进度和错误摘要；使用 CAS 状态启动、解析后事务写入、按来源行唯一约束和同内容幂等判断。
- 数据模型：分离 `departmentCode`、`additionalRequirements`、`remark`、`workLocation`、`settlementLocation`，保留原始 JSON、Sheet 和 Excel 行号。
- 条件解析：同一岗位同时读取“其他条件”和“备注”，按括号层级切分条款，输出类型、逻辑操作符、适用范围、来源字段、原文、状态、置信度、规则 ID 和版本。
- 匹配：新增逐条件 `REMARK_CONDITION` 结果和证据；复杂 OR、未知限制及资料不足均保守返回 `UNCERTAIN`，不以已识别子串放行。
- 工作经历：复用已确认职业画像中的多段工作经历，支持时间并集累计以及地区、性质、行业、岗位类型、层级、在职和核验状态。
- 学历专业口径：按标记的唯一最高学历选择专业；主修、第二学位、辅修和所有阶段等缺少完整证据的口径保持 `UNCERTAIN`。
- 地点：优先原始工作地点，其次备注明确地点，再到机关行政区划推断；落户地点不参与工作地点判定。
- 派生特征：新增按 `importId` 的预览、重建、快照和恢复接口，只更新派生解析字段。
- 前端：展示逐 Sheet 解析错误、独立字段映射、导入行错误、原始其他条件/落户地点和逐条资格结果；职业画像可手工补充工作经历。

## 3. 统一数据模型及规则设计

导入批次保存文件 SHA-256、解析版本、处理/成功/失败行数和错误摘要。岗位保存 `importId + sourceSheet + sourceRow` 的物理来源，同时保留机关代码、职位代码和原始字段 JSON。业务识别使用批次、机关和职位代码等组合信息，不再假设职位代码全局唯一。

结构化条件由现有 `job_position_feature.remark_conditions` 保存，避免新建重复条件表。每个条件包含：

- `type/nature/operator/expectedValue/scope/applicability`
- `sourceField/sourceText/matchedText`
- `status/confidence/ruleId/parserVersion`

匹配结果继续复用 `job_match_item`，新增 `REMARK_CONDITION` 项及 `MatchEvidence` 中的来源、解析状态、缺失字段和人工核验标记。录用后服务期、分配及提示信息单独展示，不作为硬性资格误排除。

## 7. 备注完整解析、部分解析、无法解析数量

保守口径：仅当全部资格条件均为高置信规则时计为“完整”；存在已分类但低置信或需核实条件时计为“部分”；只有未知资格条件时计为“无法”；纯说明和没有其他条件/备注分别列出。

| 数据 | 完整 | 部分或低置信 | 仅未知、无法解析 | 纯说明 | 无其他条件/备注 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 江西 2026 | 534 | 2,737 | 5 | 55 | 1,078 |
| 国考 2027 | 1,215 | 14,971 | 370 | 2,616 | 254 |

这些数字没有人工逐条金标准，不能解释为准确率。尤其国考复杂备注较多，系统选择扩大 `UNCERTAIN`，而不是提高表面 MATCH 数量。

## 8. 关键硬性资格条件识别情况

- `IF/THEN`：非应届条件下的工作年限、国有企事业单位性质和在职状态分别核验；应届身份未知时返回 `UNCERTAIN`。
- 条件证书：法学/法律专业的法律职业资格 A 证只对明确专业范围生效；专业类或相关专业等不确定范围不猜测。
- 工作经历：支持多段月份并集，重叠月份不重复累计；只有年份、无效日期、缺失性质/行业/地区/在职/证据时返回 `UNCERTAIN`。
- 县域乡镇事业单位：核验同县、乡镇层级、事业单位、排除学校医院及累计 5 年；明确性质不符为 `NOT_MATCH`。
- OR：基层项目或退役军人等已支持组合可按分支核验；其他无法完整建模的 OR 保持 `UNCERTAIN`。
- NOT：明确的不得报考条件被结构化并要求人工核验，不做反向误放行。
- 外语：CET 四/六级及分数门槛可核验；雅思、托福、专四专八分支在档案无成绩时保持 `UNCERTAIN`。
- 身体、民族、户籍生源、公安补充公告及复杂证书方向等仍进入人工核验清单。

## 9. 专业匹配变化统计

本次未改写现有专业目录、专业锚点或历史进面分置信度模型。软件工程 `080902`、计算机类 `0809`、明确不限、具体专业和专业类的原有测试全部通过。

新增变化是“选择哪一段教育经历参与专业匹配”：明确要求最高学历时只采用唯一标记的最高学历；无法证明主修、第二学位、辅修或所有阶段口径时不再自动 MATCH。自动测试验证了不能用较低学历的匹配专业替代最高学历专业。

没有带人工金标准的真实考生档案集，故未输出生产岗位 MATCH/NOT_MATCH 数量变化或所谓准确率；这部分需要在执行数据库迁移后用真实档案通过预览接口做人工抽样，不能从职位表单独推导。

## 11. 岗位唯一标识冲突处理结果

- 数据库物理幂等键：`(import_file_id, source_sheet, source_row)`。
- 业务核对键：批次 + 招录机关代码/名称 + 职位代码；不再依赖职位代码全局唯一。
- 两份真实表按 `部门代码 + 职位代码` 检查均为 0 个重复组合。
- 重复确认同一已导入内容时比较规范化内容并直接返回，不重复插入；映射或来源改变时要求重新上传新批次，避免覆盖收藏和匹配关系。

## 12. 历史派生数据重建结果

新增接口：

- `GET /api/job-features/parsed-preview?importId=...`：只读预览差异与地点分布。
- `POST /api/job-features/parsed-rebuild?importId=...`：首次变更前创建本地 JSON 快照，只更新解析派生字段。
- `POST /api/job-features/parsed-restore?importId=...&backupId=...`：校验批次岗位集合后恢复；其他批次拒绝恢复。

隔离 H2 中对江西 4,409 条首次预览/应用均为 4,409 条变更，应用后再次预览为 0 条变更，证明幂等。自动测试覆盖快照恢复和重复恢复（第二次 0 变更），并验证面试分等非解析字段不受影响。快照位于 `${upload.dir}/feature-backups/<importId>/`，属于每台电脑的本地恢复材料。

## 14. 未解决问题与人工核验清单

1. 复杂嵌套逻辑仍不是通用 AST 求值器；未明确支持的多层 OR/IF/NOT 会保守 `UNCERTAIN`。
2. 国考常见的公安补充公告、特殊体检标准、24 小时倒班、户籍/生源、毕业证专业名称一致、主修/本科阶段口径仍需人工核验或后续新增结构化档案字段。
3. 江西常见的医师/药师及规培方向、民族、境外学历专业条件和专业方向限制仍需人工核验。
4. 只有年份、无月份的工作经历不能可靠累计，保持 `UNCERTAIN`；在职、单位性质和证明状态缺失同理。
5. 江西地点 4,044 条为机关所在地推断，不应当作官方确认地点；360 条地点未知。
6. 尚未在生产 MySQL 执行迁移，也没有修改生产岗位、收藏、匹配、面试分或原始 Excel 数据。
7. 2026 国考官方简章在工作区不可访问，因此未加入回归。

### 部署前操作

1. 备份 MySQL 和 `${upload.dir}`。
2. 检查 `import_file`/`job_position` 待新增列是否已存在，并检查 `(import_file_id, source_sheet, source_row)` 是否有重复；确认无冲突后执行 `src/main/resources/db/hf_migration_general_exam_import.sql` 一次。
3. 部署并重启前后端。
4. 对目标批次先调用 `parsed-preview`，人工抽查差异；确认后再调用 `parsed-rebuild`，保存返回的 `backupId`。
5. 另一台电脑拉取共享代码后同样执行数据库预检和迁移；不需要复制本机绝对路径或真实测试文件。若需要跨电脑恢复快照，应同时安全复制对应 `feature-backups` 目录。
